# Dereknet CLM v5.0

Автоматическое создание договоров NDA для ТОО «Dereknet» на Google Workspace.
Сотрудник вводит БИН контрагента — система проверяет его в государственных реестрах,
собирает двуязычный договор из шаблона, ставит подпись директора, сохраняет
Google Документ и PDF, пишет в реестр и отправляет письмо.

## Как это работает

```
                    ┌─────────────────────────────┐
Сотрудник ─────────►│  Веб-форма (Index.html)     │  ← основной путь
                    │  БИН → проверка → договор   │
                    └──────────────┬──────────────┘
                                   │
Файл в «1. Входящие» ──────────────┤  ← запасной путь, триггер раз в 5 мин
                                   ▼
        ┌──────────────────────────────────────────────────┐
        │  1. Распознавание      OpenAI Vision / Drive OCR │
        │  2. Контрольная сумма БИН        локально        │
        │  3. Проверка контрагента         реестры РК      │
        │  4. Блокировка при риске банкрот / лжепредприятие│
        │  5. Полнота данных                               │
        │  6. Сборка из шаблона  тело + колонтитулы + сноски│
        │  7. Контроль: не осталось ли {{плейсхолдеров}}   │
        │  8. Подпись директора            PNG             │
        └──────────────────────┬───────────────────────────┘
                               ▼
     Google Документ + PDF  →  Реестр договоров  →  Письмо инициатору
```

Любая проблема на любом шаге → файл в «4. Требует проверки» + записка «что не так»
рядом с ним + письмо человеку простым языком.

## Структура

```
CLM/
├── src/                     ← код проекта Apps Script (заливается как есть)
│   ├── appsscript.json      манифест: scopes, Drive API v3, веб-приложение
│   ├── 01_Config.gs         настройки, реквизиты Dereknet, доступ к Script Properties
│   ├── 02_Setup.gs          мастер установки, автопоиск шаблонов, диагностика
│   ├── 03_Pure.gs           чистая логика — БИН, падежи, плейсхолдеры, тексты ошибок
│   ├── 04_Extract.gs        распознавание: картинка, PDF, Google Документ, текст
│   ├── 05_Lookup.gs         проверка контрагента по БИН, отметки риска
│   ├── 06_Render.gs         сборка договора, подпись, нумерация
│   ├── 07_Pipeline.gs       конвейер обработки папки «Входящие»
│   ├── 08_Log.gs            журнал, реестр договоров, статистика
│   ├── 09_Notify.gs         письма: успех, проблема, утренняя сводка
│   ├── 10_Menu.gs           меню в Google Таблице
│   ├── 11_WebApp.gs         серверная часть веб-формы
│   └── Index.html           веб-форма для сотрудников
├── tests/                   ← локальные тесты (Node.js, без Google)
│   ├── pure.test.js         70 проверок логики
│   └── syntax.test.js       синтаксис, дубли имён, целостность связей
├── docs/                    ← документация
└── legacy/                  ← версия 4.2.1, для истории
```

Порядок файлов важен: Apps Script выполняет объявления верхнего уровня
в алфавитном порядке имён. Числовые префиксы это гарантируют.

## Разработка

```bash
npm test
```

Запускает обе проверки без обращения к Google:

- **`pure.test.js`** — контрольная сумма БИН на реальных номерах, согласование падежей,
  разбор плейсхолдеров, транслитерация, имена файлов, тексты ошибок.
- **`syntax.test.js`** — синтаксис всех `.gs` и браузерного кода, отсутствие
  дублирующихся имён функций и глобальных переменных (в Apps Script второе объявление
  молча перекрывает первое), совпадение вызовов `google.script.run` с серверными
  функциями, целостность ключей настроек и словаря плейсхолдеров.

Проверки в самом Google (нужен доступ к Диску):

| Что | Где |
|---|---|
| Полная диагностика | CLM → 🛠 → 🩺 Проверить систему |
| Пробный договор без публикации | CLM → 🛠 → 🧪 Тест: собрать пробный договор |
| Проверка БИН и реестров | CLM → 🛠 → 🧪 Тест: проверить БИН |

### Заливка кода

Вручную — копированием файлов в редактор Apps Script.
Или через [clasp](https://github.com/google/clasp):

```bash
npm install -g @google/clasp
clasp login
cp .clasp.json.example .clasp.json     # вписать scriptId
clasp push
```

## Настройки (Script Properties)

В коде нет ни одного ID. Всё создаётся мастером установки и хранится в свойствах скрипта.

| Ключ | Обязателен | Что это |
|---|---|---|
| `ROOT_FOLDER_ID` | да | Корневая папка (лучше — Общий диск) |
| `INBOX_FOLDER_ID` … `TEMPLATE_FOLDER_ID` | да | Рабочие папки, создаёт мастер |
| `LOG_SHEET_ID` | да | Таблица журнала и реестра |
| `KZ_TEMPLATE_ID` | да | Шаблон NDA для Казахстана (Google Документ) |
| `US_TEMPLATE_ID` | нет | Шаблон для США; без него заявки США уходят на ручную обработку |
| `SIGNATURE_FILE_ID` | нет | PNG подписи директора; без него в договоре прочерк |
| `OPENAI_API_KEY` | да | Ключ OpenAI для распознавания |
| `MANAGER_EMAIL` | да | Куда слать уведомления о проблемах и сводку |
| `LOOKUP_API_URL` | нет | Платный API проверки контрагентов, `{BIN}` в шаблоне URL |
| `LOOKUP_API_KEY` | нет | Заголовок `Authorization` для него |
| `WEBAPP_URL` | нет | Ссылка на опубликованную форму (для меню) |
| `REGISTER_SEQ` | авто | Счётчик номеров договоров, формат `2026:42` |

## Ограничения

- **Договор — черновик.** Подпись директора в нём факсимильная (картинка), а не ЭЦП.
  Юридическую силу документ получает после подписания сторонами.
  Переход на ЭЦП НУЦ РК — этап 2 в [РАЗВИТИЕ.md](docs/РАЗВИТИЕ.md).
- **Проверка контрагента не гарантирована.** Официального бесплатного API реестров РК
  нет; система читает публичный агрегатор и честно сообщает, если проверка не прошла.
  Для гарантии подключите платный API через `LOOKUP_API_URL`.
- **Файлы Word** напрямую не читаются — нужно сохранить как Google Документ.
- **Один шаблон на страну.** Разные виды договоров — этап 7.
