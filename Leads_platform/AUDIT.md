## ✅ Исправлено в этом коммите

1. **telegram_parser.py — дубликаты обработчиков при реконнекте.** При каждом обрыве связи
   обработчик `NewMessage` регистрировался заново на тот же клиент → после N реконнектов каждое
   сообщение скорилось N раз (двойные траты OpenAI, дубли вердиктов). Теперь регистрируется один раз
   (флаг `handler_added`).
2. **telegram_parser.py — тесный цикл реконнектов.** Если ни одна группа не резолвится
   (опечатка в юзернейме), парсер переподключался к Telegram без паузы в бесконечном цикле.
   Теперь: понятная ошибка в UI + пауза 60 сек.
3. **telegram_parser.py — `get_me` каждые 5 секунд** (~17 000 вызовов к Telegram в сутки впустую).
   Теперь keepalive раз в минуту, heartbeat в UI остался частым.
4. **twogis_parser.py — упавший скан завис навсегда.** Неожиданная ошибка убивала задачу,
   но `running` оставался `true`: UI вечно показывал «Сканирует», перезапуск был невозможен
   до редеплоя. Теперь `try/finally` гарантирует сброс статуса и текст ошибки в UI.
5. **twogis_parser.py — ссылка на 2GIS вела в Алматы для любого города** (hardcoded `/almaty/`).
   Теперь безгородская ссылка `2gis.kz/firm/{id}` — 2GIS сам редиректит на нужный город.
6. **main.py — `GET /settings` отдавал пароль Instagram и строку сессии любому в интернете.**
   API без авторизации, а в настройках лежат `ig_password` и `ig_session_b64` — этого хватало,
   чтобы полностью угнать Instagram-аккаунт. Теперь эти ключи вырезаются из ответа.
7. **Leads.jsx / Dashboard.jsx — белый экран от одного лида.** Лид с каналом вне списка
   (whatsapp/2gis/telegram/instagram) ронял всю страницу CRM (`cm.icon` на `undefined`).
   Теперь есть фолбэк-иконка.
8. **Leads.jsx — кнопки статуса выглядели мёртвыми.** Клик по воронке / «Одобрить ответ»
   обновлял базу, но открытая карточка не перерисовывалась. Теперь карточка синхронизируется.

## 🔴 Критично (следующий приоритет — до продажи)

1. **Нет авторизации вообще.** Любой, кто узнает URL на Railway, может: читать и удалять всех
   лидов, менять настройки, останавливать/запускать парсеры, публиковать комментарии и слать DM
   от имени Instagram-аккаунта. Для продажи проекта это блокер №1. Бесплатное решение: секретный
   ключ в env (`APP_SECRET`) + проверка заголовка `X-Api-Key` в middleware на всех эндпоинтах +
   простой экран входа на фронте (ключ в localStorage).
2. **Дедупликация ломается после 500 лидов.** Оба Telegram-парсера проверяют дубли перебором
   `GET /leads?limit=500`. Когда лидов станет больше 500, старые профили начнут сохраняться
   повторно — вернётся баг «написали одному человеку дважды» (нарушение правила №2 CLAUDE.md).
   Решение: эндпоинт `GET /leads/exists?profile_url=...` (точечный запрос) + UNIQUE-индекс
   на `profile_url` в Supabase как страховка.
3. **`GET /stats` врёт после 1000 лидов.** Считает по всем строкам, но Supabase по умолчанию
   отдаёт максимум 1000 — счётчики Dashboard молча занизятся. Решение: считать через
   `count="exact"` запросы вместо выгрузки всех строк.

## 🟠 Средние

4. **24/7 зависит от настройки Railway.** Парсеры — это asyncio-задачи внутри веб-процесса.
   Если в сервисе Railway включён режим сна при простое (App Sleeping / serverless idle),
   контейнер замораживается без HTTP-трафика → парсеры останавливаются. Это и есть вероятная
   причина «останавливается, когда закрываю сайт». Проверить: Railway → сервис → Settings →
   выключить sleeping. Стоит добавить `/healthz` и внешний пинг (UptimeRobot, бесплатно).
5. **2GIS-скан → шторм уведомлений в Telegram.** `create_lead` шлёт уведомление на КАЖДОГО лида.
   Массовый скан 2GIS сохраняет десятки лидов подряд → Telegram отдаёт `429 Too Many Requests`,
   часть уведомлений теряется. Решение: для холодных outbound-лидов 2GIS слать одно сводное
   уведомление в конце скана, а не по одному.
6. **Чёрный список — косметика.** В Настройках список ведётся в локальном состоянии React,
   на бэкенд не уходит, парсеры его не читают. Номер из чёрного списка всё равно получит сообщение.
   Либо подключить (settings + проверка в парсерах), либо убрать до реализации.
7. **Рабочие часы — косметика.** `work_start` / `work_end` сохраняются в settings, но ни один
   парсер их не соблюдает. CLAUDE.md обещает Smart Pause вне рабочих часов — сейчас не работает.
8. **Bot API парсер без in-memory кэша дублей.** В отличие от Telethon, `telegram_bot_parser`
   не занимает слот в кэше до async-сохранения → два быстрых сообщения от одного автора могут
   создать двух лидов. Продублировать паттерн `_seen_profiles` из telegram_parser.py.

## 🟡 Мелкие

9. **Эфемерный диск Railway.** `tg_session.session` и `ig_sessions/` пишутся на диск контейнера,
   который стирается при каждом редеплое. Сейчас спасают env `TG_SESSION_B64` и настройка
   `ig_session_b64` — работает, но стоит помнить: без них после редеплоя сессии теряются.
10. **Бандл фронтенда 649 КБ одним чанком.** Не критично, но для профессионального вида —
    code-splitting (recharts грузить лениво только на Dashboard).
11. **catch-all `/{full_path:path}` отдаёт index.html с кодом 200 на несуществующие пути.**
    Запрос к опечатке в API вернёт HTML вместо `404`, фронт споткнётся на `res.json()`. Мелочь.
12. **Instagram reply-monitor полагается на `replied_to_comment_id`.** У части объектов
    instagrapi этого поля нет — часть ответов авторов может теряться (не краш, но пропуски).
