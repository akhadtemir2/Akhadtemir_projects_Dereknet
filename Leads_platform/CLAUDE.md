## 1. О компании

**BaiTech** — AI-автоматизация для малого и среднего бизнеса Казахстана.

- Сайт: https://baitech.kz · Instagram: @BaittechKZ · Атырау, Казахстан
- Услуги: AI-чат-боты (WhatsApp / Telegram / Instagram), CRM (AinaDivo), автоответы, голосовые боты
- Клиенты: малые бизнесы(главный приоритет), средний бизнес,магазины, клиники, автосервисы, рестораны, салоны, стройка

### Кого ищем — портрет идеального лида (ICP)
Главная и единственная аудитория, которую платформа ищет и квалифицирует, — **малый и средний бизнес Казахстана.** Это собственники и управляющие, а не корпорации и не частные лица. AI-агент должен ориентироваться на этот портрет при поиске, скоринге и пометке «🔥 горячий».

- **Кто:** владелец / директор / администратор небольшого бизнеса (ИП, ТОО). Один человек принимает решения и платит.
- **Сферы:** магазины, клиники и стоматологии, автосервисы, рестораны/кафе, салоны красоты, стройка/ремонт. (Приоритет — те, у кого много входящих заявок и нет менеджера, чтобы их обрабатывать.)
- **География:** старт — Атырау, далее крупные города КЗ (Алматы, Астана, Актобе, Шымкент).
- **Сигналы боли (повышают балл лида):** «не успеваю отвечать», «много заявок», «теряю клиентов», ручная переписка в WhatsApp/Instagram, нет CRM, отвечает сам владелец.
- **Размер:** микро- и малый бизнес (примерно 1–30 сотрудников). Средний — верхняя граница.
- **Кого пропускаем (не наш лид):** крупные компании и госструктуры, фрилансеры/физлица без бизнеса, бизнесы вне КЗ, те, кому уже писали (проверка по БД), чёрный список.

> Этот ICP — критерий для скоринга. Чем точнее лид совпадает с портретом и сигналами боли, тем выше его балл и тем раньше он попадает в «🔥 Горячие».

## 2. Что мы на самом деле строим

Изначальная идея звучала как «бот, который сам пишет людям в соцсетях». После анализа рынка мы **переформулировали** её в то, что реально нужно владельцу и реально работает в Казахстане:

> **BaiTech Lead Hub — это один экран, куда стекаются ВСЕ лиды со всех каналов, и AI-ассистент, который их встречает, квалифицирует и греет за тебя.**

Главная боль владельца — не «мало сообщений», а «я устал проверять Instagram, WhatsApp, 2GIS, Telegram по отдельности». Значит ядро продукта — **единый входящий ящик (Unified Inbox) + AI-ассистент**, а не армия ботов-спамеров.

Философия остаётся прежней: **«Ты задаёшь цель — агент делает остальное».** Но «делать» = принимать, отвечать, квалифицировать и находить лидов, а не рассылать спам с личных аккаунтов.

## 3. Каналы: решение под реальность Казахстана (важно)

Это самое важное изменение относительно первого плана. Данные по рынку КЗ (2025): WhatsApp — 89% пользователей, Instagram — 63% населения и главная площадка для малого бизнеса, 2GIS — 113 700 компаний в справочнике, Telegram — всего ~25%, Facebook — ~9%, LinkedIn — практически не используется.

| Канал | Роль в проекте | Приоритет | Почему |
|-------|----------------|-----------|--------|
| **WhatsApp** | Главный канал общения и офферов | 🥇 Phase 1 | №1 мессенджер КЗ. Без него продукт мёртв. Подключаем через **официальный WhatsApp Business API (WABA)**, не через личный номер. |
| **2GIS** | Источник холодных лидов (парсинг бизнесов Атырау/КЗ) | 🥇 Phase 1 | Самый быстрый и легальный способ получить первые контакты. Не требует логина, низкий риск. |
| **Instagram** | Входящие из Direct + комментарии | 🥈 Phase 2 | Главная соцсеть КЗ для малого бизнеса. Подключаем входящие через официальный Instagram/Meta API. |
| **Telegram** | Мониторинг чатов + входящие | 🥈 Phase 2 | Лояльнее к автоматизации, но аудитория меньше. Через Telegram Bot API / Telethon. |
| **Facebook** | Опционально | 🥉 Phase 3 | Слабая аудитория в КЗ (~9%). Высокий риск бана при автоматизации. Делаем только если останется ресурс. |
| **LinkedIn** | ❌ ВЫРЕЗАНО | — | В Казахстане практически не работает для МСБ. Высокий риск бана, нулевая отдача. Не тратим время. |

**Вывод:** холодный поиск — это 2GIS (легально и быстро). Общение и прогрев — WhatsApp (где сидят все клиенты). Всё остальное — позже.

## 4. Главный архитектурный принцип: безопасность аккаунтов

Первый план опирался на Playwright-ботов, которые логинятся в личные аккаунты Facebook/LinkedIn и шлют сообщения. **Это самый быстрый способ потерять аккаунты и репутацию.** Платформы вычисляют такую автоматизацию за минуты.

Наши правила:

1. **Официальные API в приоритете.** WhatsApp Business API, Telegram Bot API, Instagram Graph API — это легальные каналы, которые не банят за автоматизацию. Личные аккаунты + браузерная автоматизация — крайняя мера и только Phase 3.
2. **Inbound > Outbound.** Главная ценность — собрать и обработать входящие лиды в одном месте (модель Wazzup/amoCRM, которая реально работает в СНГ). Холодная рассылка — вторична.
3. **2GIS — это парсинг публичных данных,** а не рассылка. Низкий риск. Поэтому он в Phase 1.
4. **Human Review Gate по умолчанию включён** на старте: AI генерирует — человек одобряет — потом отправка.

## 5. MVP: что делаем прямо сейчас (Phase 0 — Интерфейс)

Владельцу сейчас нужно **увидеть интерфейс и логику без ключей и без реальной отправки.**

Phase 0 = полностью рабочий фронтенд на **мок-данных (demo mode)**:

- Все экраны кликабельны и наполнены реалистичными фейковыми лидами.
- Кнопки «Запустить агентов», «Одобрить», «Передать менеджеру» работают на уровне UI и меняют состояние в локальном состоянии приложения.
- Никаких API-ключей, никакой реальной отправки. Вверху бейдж «🟡 DEMO MODE».
- Цель Phase 0 — чтобы владелец походил по продукту, почувствовал его и сказал, что менять, ДО написания бэкенда.

Только после одобрения интерфейса подключаем реальный бэкенд и каналы.

## 6. Интерфейс (UI/UX)

### Общие требования (предпочтения владельца — приоритет)
- **Минимализм.** Никаких лишних данных на экране. Если показатель не помогает принять решение — убрать.
- **Адаптивность** под все устройства (телефон, планшет, десктоп).
- **Тёмная тема.**
- **Навигация — слева** (вертикальный сайдбар с иконками).
- **Фирменные цвета:**
  - `#7A8B69` — приглушённый зелёный (акценты, активные состояния, кнопки действия)
  - `#D4C6B9` — песочно-бежевый (вторичные элементы, текст на тёмном, рамки)
  - Фон тёмный (например `#1A1C1A` / `#222420`), текст — светлый бежевый.
- Шрифт читаемый, крупные кликабельные зоны (продукт для занятого предпринимателя, а не для аналитика).

### Разделы (упрощено с 6 до 4)
Первый план содержал 6 вкладок. Аналитика без данных — мёртвый груз, а «Шаблоны» можно убрать в настройки. Оставляем **4 раздела:**

**1. Главная / Входящие (Dashboard + Inbox)**
- 4 счётчика и не больше: новых лидов · ответили · 🔥 горячие · конверсия %
- Большая кнопка `▶ Запустить агентов` / `⏸ Пауза`
- Статус каждого канала: 🟢 работает / 🟡 медленно / 🔴 ошибка
- Лента последних входящих лидов (живая) — это и есть «единый ящик»
- График активности за 7 дней (один, простой)

**2. Лиды (CRM)**
- Таблица с фильтрами: Все · Новые · Ответили · 🔥 Горячие · Клиенты
- Колонки: имя · тип бизнеса · канал · статус · дата
- Карточка лида: профиль, история переписки, заметки, кнопки `Одобрить ответ` и `Передать менеджеру`
- Воронка статусов: Найден → Написан → Ответил → Заинтересован → Клиент

**3. Агенты (управление)**
- Карточка на каждый канал: вкл/выкл, лимит/день (слайдер), язык RU/KZ/Оба, режим `Авто` или `С проверкой`, ключевые слова, кнопка `Тест (3 сообщения)`
- Здесь же — редактор шаблонов/промптов под типы бизнеса (автосервис, ресторан, салон, магазин, клиника, стройка). Тест промпта: ввёл пост → увидел результат.

**4. Настройки**
- Рабочие часы агентов (например 9:00–18:00)
- API-ключи (OpenAI, каналы) — пока пусто, заглушки
- Подключённые аккаунты (WhatsApp/Instagram/Telegram)
- Чёрный список (кому никогда не писать)
- Telegram-уведомления владельцу

> **Аналитика** появляется отдельной вкладкой только в Phase 2, когда накопятся реальные данные. На старте её нет — это осознанно.

## 7. Технический стек

- **Frontend:** React + Tailwind CSS (тёмная тема, фирменные цвета)
- **Backend:** FastAPI (Python) — подключаем в Phase 1, не в Phase 0
- **БД:** SQLite → PostgreSQL (на продакшене)
- **AI:** OpenAI GPT-4o-mini (генерация и определение языка)
- **Каналы:** WhatsApp Business API, Telegram Bot API / Telethon, Instagram Graph API, парсер 2GIS
- **Уведомления:** Telegram Bot API
- **Фоновые задачи:** для MVP — фоновые процессы FastAPI с **обязательным восстановлением прерванных сессий при старте** `main.py`. В будущем (при росте) — очередь Celery + Redis.

## 9. Умные фишки (оставляем — они сильные)

- **Smart Pause** — агент сам замедляется при 3 отказах подряд или подозрительном поведении канала.
- **Human Review Gate** — режим «AI сгенерировал → ты одобрил → отправка». **Включён по умолчанию на старте.**
- **Test Mode** — прогон агента на 3 сообщениях перед полным запуском.
- **Best Time** (Phase 2, когда есть данные) — отправка в часы активности лидов.

## 10. Модель данных (база)

```sql
CREATE TABLE leads (
    id INTEGER PRIMARY KEY,
    channel TEXT,          -- whatsapp / instagram / telegram / 2gis / facebook
    name TEXT,
    profile_url TEXT,
    phone TEXT,
    business_type TEXT,
    language TEXT,          -- ru / kz
    status TEXT,            -- found / messaged / replied / interested / converted
    source TEXT,            -- inbound / outbound (входящий или найден нами)
    last_message TEXT,
    notes TEXT,
    is_hot INTEGER,         -- 0/1 флаг "горячий"
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

CREATE TABLE messages (        -- история переписки для единого ящика
    id INTEGER PRIMARY KEY,
    lead_id INTEGER,
    direction TEXT,            -- in / out
    text TEXT,
    approved_by_human INTEGER, -- 0/1 (для Human Review Gate)
    created_at TIMESTAMP
);

CREATE TABLE agent_logs (
    id INTEGER PRIMARY KEY,
    channel TEXT,
    action TEXT,
    target TEXT,
    result TEXT,
    created_at TIMESTAMP
);

CREATE TABLE settings (
    key TEXT PRIMARY KEY,
    value TEXT
);
```

> Отличие от первого плана: добавлены таблица `messages` (для единого ящика и истории), поля `source`, `is_hot`, `approved_by_human`. Каналы переименованы под реальные (whatsapp/instagram вместо linkedin).

## 14. Правила кода

1. Все тексты — только через OpenAI GPT-4o-mini.
2. Никогда не писать одному человеку дважды (проверка по БД).
3. Всегда случайные паузы между действиями.
4. Сессии каналов сохранять и **восстанавливать при перезапуске**.
5. Каждое действие логировать в `agent_logs`.
6. `try/except` везде — агент не должен падать.
7. После каждого действия обновлять статус лида.
8. Официальные API > браузерная автоматизация личных аккаунтов.
9. Human Review Gate включён по умолчанию.
