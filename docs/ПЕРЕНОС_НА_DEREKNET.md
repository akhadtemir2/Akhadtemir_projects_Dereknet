# Перенос CLM с учебного аккаунта на Google Workspace Dereknet

## Зачем это делать (и почему срочно)

Сейчас вся система — папки, шаблоны, журнал, скрипт, триггеры — принадлежит аккаунту
**`atemir23@apec.edu.kz`**. Это аккаунт учебного заведения в чужом Google Workspace.

| Риск | Последствие |
|---|---|
| Аккаунт отключат при отчислении/выпуске | Договоры, реестр и журнал исчезнут вместе с ним |
| Администратор APEC видит все файлы | Реквизиты контрагентов и договоры Dereknet — в чужой инфраструктуре |
| Триггеры выполняются от имени владельца | Скрипт остановится в тот же день, когда отключат аккаунт |
| Письма уходят с адреса `@apec.edu.kz` | Контрагент получает договор Dereknet с учебной почты |
| Лимит писем на учебном аккаунте | Обычно 100/сут против 1500/сут на корпоративном |

**Проверено 27.08.2026:** домен `dereknet.com` уже обслуживается Google Workspace
(MX-записи Google, SPF `include:_spf.google.com`). Отдельно ничего покупать не нужно.

---

## План: две фазы

Доступ к Admin Console есть у другого человека, поэтому перенос разбит так, чтобы
**не ждать администратора для главного**.

| | Фаза 1 — без администратора | Фаза 2 — с администратором |
|---|---|---|
| **Что даёт** | Система уходит с учебного аккаунта на `info@dereknet.com`. Главный риск закрыт | Файлы переходят во владение **организации**, а не человека |
| **Кто владелец файлов** | Аккаунт `info@dereknet.com` | Организация Dereknet (Общий диск) |
| **Время** | 40–60 минут | 15 минут |
| **Когда** | Сейчас | Когда администратор будет свободен |
| **Что если фазу 2 не сделать** | Работает, но при закрытии `info@` файлы придётся передавать вручную | — |

Фаза 2 после фазы 1 делается одним перетаскиванием: перемещение из «Мой диск»
аккаунта `info@dereknet.com` на Общий диск той же организации — внутреннее,
ID файлов не меняются, ничего не ломается.

Памятка для администратора — отдельным файлом: [ПАМЯТКА_АДМИНИСТРАТОРУ.md](ПАМЯТКА_АДМИНИСТРАТОРУ.md).

# ФАЗА 1 — уходим с учебного аккаунта

## Шаг 0. Проверить, что `info@dereknet.com` — полноценный аккаунт

⚠️ **Это обязательная проверка, без неё дальше идти нельзя.**

В Google Workspace `info@` часто заводят как **группу** или **алиас**, а не как
пользователя. Группа не может владеть проектом Apps Script и не может запускать триггеры.

Как проверить: откройте окно браузера в режиме инкогнито → `accounts.google.com` →
войдите как `info@dereknet.com`.

| Результат | Что делать |
|---|---|
| Вход прошёл, открылся Google Диск | ✅ Это пользователь, продолжайте |
| «Аккаунт не найден» / «Это группа» | Нужен другой аккаунт — попросите администратора создать `clm@dereknet.com` |
| Пароля нет ни у кого | Попросите администратора сбросить пароль или создать `clm@dereknet.com` |

Дальше в инструкции этот аккаунт называется **аккаунт-владелец**.

## Шаг 1. Создать папку под аккаунтом-владельцем

Под `info@dereknet.com`:

1. Google Диск → **Мой диск** → **Создать → Папка** → назвать `Dereknet CLM`.
2. Открыть папку, скопировать **ID** из адресной строки — это часть после `/folders/`.
   Пример: `https://drive.google.com/drive/folders/1AbCdEf...` → ID = `1AbCdEf...`
3. Нажать на папку правой кнопкой → **Открыть доступ** → добавить
   `atemir23@apec.edu.kz` с правами **Редактор** *(временно, снимем на шаге 8)*.

## Шаг 2. Перенести шаблон и подпись

Под `atemir23@apec.edu.kz` найти и **скопировать** в новую папку:

| Что | Как переносить |
|---|---|
| Шаблон NDA (Google Документ) | Правый клик → **Создать копию** → перетащить копию в `Dereknet CLM` |
| PNG с подписью директора | Скачать и загрузить заново под `info@` |
| Готовые договоры (папка Contracts) | Выделить всё → перетащить в `Dereknet CLM` (по желанию, можно позже) |

> **Почему копия, а не перемещение.** Google не передаёт владение файлом между
> разными доменами. Перемещённый файл остался бы во владении `apec.edu.kz` —
> то есть проблема бы не решилась. Копия принадлежит тому, кто её сделал.
> Поэтому копию делает **аккаунт-владелец**: откройте шаблон под `info@dereknet.com`
> (доступ у него уже есть) и нажмите **Файл → Создать копию → в папку Dereknet CLM**.

Старый журнал и реестр копировать не нужно — новые создаст мастер установки.
Если нужна история, скопируйте старую таблицу отдельно как архив.

## Шаг 3. Создать таблицу-журнал и проект скрипта

Под **аккаунтом-владельцем**:

1. В папке `Dereknet CLM` → **Создать → Google Таблицы** → назвать `Dereknet CLM — Журнал`.
2. В таблице: **Расширения → Apps Script**.
3. Назвать проект `Dereknet CLM`.

## Шаг 4. Залить код

В редакторе Apps Script:

1. Удалить содержимое файла `Код.gs` (он же `Code.gs`).
2. Создать файлы и вставить в них код из папки `src/`:

   | Файл в Apps Script | Тип | Откуда |
   |---|---|---|
   | `01_Config` … `11_WebApp` | Скрипт | одноимённые `.gs` из `src/` |
   | `Index` | **HTML** | `src/Index.html` |

   > Порядок файлов важен: Apps Script выполняет объявления верхнего уровня
   > в алфавитном порядке имён. Числовые префиксы это гарантируют — не переименовывайте
   > и не убирайте цифры.

3. **Манифест:** ⚙️ **Настройки проекта** → поставить галочку
   «Показывать файл манифеста appsscript.json в редакторе».
   Вернуться в редактор, открыть `appsscript.json`, заменить содержимым `src/appsscript.json`.

4. **Службы:** слева **Службы (+)** → найти **Drive API** → версия **v3** → **Добавить**.

5. Сохранить (Ctrl+S).

> Быстрее — через [clasp](https://github.com/google/clasp):
> ```bash
> npm install -g @google/clasp
> clasp login                              # войти как info@dereknet.com
> cp .clasp.json.example .clasp.json       # вписать scriptId из настроек проекта
> clasp push
> ```

## Шаг 5. Запустить мастер установки

1. Обновить вкладку с таблицей — появится меню **📄 CLM**.
2. **CLM → 🛠 Установка и проверка → 🚀 Запустить мастер установки**.
3. Вставить **ID папки** `Dereknet CLM` из шага 1.
4. Google попросит разрешения → **Разрешить**.
   Появится «Google не проверил это приложение» → **Дополнительные настройки →
   Перейти к Dereknet CLM (небезопасно)**. Это нормально: приложение написано
   внутри компании и не публиковалось в магазине Google.

Мастер создаст папки «1. Входящие» … «6. Шаблоны», листы «Журнал», «Реестр договоров»,
«Справочник ошибок» и включит автозапуск.

## Шаг 6. Досоздать то, что нельзя автоматизировать

1. Перенести шаблон NDA и PNG подписи из шага 2 в созданную папку **«6. Шаблоны»**.
   > Шаблон должен быть **Google Документом**. Если это `.docx` — откройте его
   > и нажмите **Файл → Сохранить как Google Документ**.
2. **CLM → 🛠 → 🔍 Найти шаблоны и подпись**.
3. **CLM → 🛠 → 🔑 Указать ключ OpenAI**.
   > Заведите **новый** ключ на platform.openai.com под аккаунтом компании
   > и **отзовите старый**: он лежал в проекте на учебном аккаунте и считается
   > скомпрометированным.
4. **CLM → 🛠 → 📧 Указать email ответственного**.

## Шаг 7. Проверить

| Что нажать | Что должно быть |
|---|---|
| **CLM → 🛠 → 🩺 Проверить систему** | Все пункты ✅, ни одного ❌ |
| **CLM → 🛠 → 🧪 Тест: собрать пробный договор** | «✅ Шаблон исправен» |
| **CLM → 🛠 → 🧪 Тест: проверить БИН** → `190440019884` | «✅ Контрольная сумма верна» |

Затем боевая проверка: положить в **«1. Входящие»** реальный документ контрагента,
подождать 5 минут, проверить письмо и содержимое договора.

## Шаг 8. Опубликовать веб-форму

1. Редактор скрипта → **Начать развёртывание → Новое развёртывание**.
2. Тип: **Веб-приложение**. Описание: `CLM v5.0`.
3. **Запуск от имени: Я** (`info@dereknet.com`).
   > Именно так сотрудникам не нужны никакие права на Google Диск —
   > файлами оперирует система, а не человек.
4. **Кто имеет доступ: Все пользователи в организации Dereknet**.
5. Развернуть → скопировать ссылку.
6. В таблице: **CLM → 🔗 Открыть форму заявки** → вставить ссылку.
7. Разослать сотрудникам ссылку вместе с [ИНСТРУКЦИЯ_ДЛЯ_СОТРУДНИКА.md](ИНСТРУКЦИЯ_ДЛЯ_СОТРУДНИКА.md).

## Шаг 9. Отключить старую систему

Под `atemir23@apec.edu.kz`:

1. Открыть старый проект Apps Script → **Триггеры** (иконка часов) → удалить **все**.
   > Пока этого не сделано, две системы работают параллельно и могут выдать
   > два договора с разными номерами на одну заявку.
2. Снять доступ `atemir23@apec.edu.kz` к папке `Dereknet CLM`.
3. Отозвать старый ключ OpenAI на platform.openai.com.

**На этом фаза 1 закончена — система больше не зависит от учебного аккаунта.**

# ФАЗА 2 — передаём файлы организации

Делается, когда администратор Workspace будет доступен. Инструкция для него —
[ПАМЯТКА_АДМИНИСТРАТОРУ.md](ПАМЯТКА_АДМИНИСТРАТОРУ.md).

1. **Администратор** создаёт Общий диск `Dereknet CLM` и добавляет `info@dereknet.com`
   Менеджером.
2. **Вы**, под `info@dereknet.com`, перетаскиваете содержимое папки `Dereknet CLM`
   из «Мой диск» на **Общий диск → Dereknet CLM**.
   Это перемещение внутри одной организации: **ID файлов не меняются**, скрипт
   продолжает работать без единой правки.
3. **CLM → 🛠 → 🩺 Проверить систему** — убедиться, что всё ✅.
4. Проект Apps Script переносить не нужно: он привязан к таблице и переезжает вместе с ней.

После этого владельцем всего является организация Dereknet. Даже если аккаунт
`info@dereknet.com` когда-нибудь закроют, файлы, договоры и реестр останутся.

## Если что-то пойдёт не так

| Симптом | Причина | Решение |
|---|---|---|
| «Аккаунт не найден» при входе в `info@` | Это группа, а не пользователь | Нужен `clm@dereknet.com`, см. памятку администратору |
| «У вас нет доступа к файлу» при запуске мастера | ID папки чужого аккаунта | Проверить, что ID из папки, созданной под `info@` |
| Меню 📄 CLM не появилось | Не сохранён код или не обновлена вкладка | Ctrl+S в редакторе, затем F5 в таблице |
| «Drive API не подключён» | Не добавлена служба | Редактор → Службы (+) → Drive API → **v3** |
| Договоры создаются, писем нет | Не задан email ответственного | CLM → 🛠 → 📧 |
| Форма отдаёт «Отказано в доступе» | Развёрнута с доступом «Только я» | Переразвернуть с «Все в организации» |
| Триггеры не срабатывают | Владелец не подтвердил доступ | Запустить `processInbox` вручную и разрешить |
| Скопированный шаблон всё ещё принадлежит apec | Копию сделал не тот аккаунт | Копию должен делать **`info@dereknet.com`** через Файл → Создать копию |

### Откат

Ничего необратимого до шага 9: старая система остаётся на месте и продолжает работать.
Чтобы вернуться — удалите триггеры на новом проекте и оставьте старые.
