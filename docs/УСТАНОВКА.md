# ЧАСТЬ 1 — Установка (шаги 1–15)

### 1. Открыть Google Диск нужным аккаунтом

`drive.google.com` → аватарка справа сверху должна быть **office@dereknet.com**.
Если другой аккаунт — переключиться.

### 2. Создать таблицу

**Создать → Google Таблицы**. Назвать вверху: `Dereknet CLM`

Эта таблица станет журналом и реестром договоров. Отдельную создавать не нужно.

### 3. Открыть редактор кода

Меню **Расширения → Apps Script**. Откроется новая вкладка.

### 4. Вставить основной код

1. Открыть `github.com/akhadtemir2/Akhadtemir_projects_Dereknet/blob/main/build/Code.gs`
2. Справа над кодом — иконка двух страничек, **Copy raw file**
3. В Apps Script открыть файл **`Код.gs`** (уже существует) → **Ctrl+A** → **Ctrl+V**

### 5. Вставить форму

1. Открыть `.../blob/main/build/Index.html` → **Copy raw file**
2. В Apps Script: **Файлы → + → HTML**
3. Имя: **`Index`** (ровно так, без `.html`)
4. **Ctrl+A** → **Ctrl+V**

### 6. Вставить настройки проекта

1. Слева **⚙️ Настройки проекта** → галочка «Показывать файл манифеста appsscript.json»
2. Вернуться в **Редактор** (иконка `<>`), открыть появившийся `appsscript.json`
3. Скопировать из `.../blob/main/build/appsscript.json`
4. **Ctrl+A** → **Ctrl+V**

### 7. Сохранить

**Ctrl+S**

Проверка: слева должно быть ровно 3 файла — `Код.gs`, `Index.html`, `appsscript.json`.

### 8. Обновить таблицу

Вернуться во вкладку с таблицей, нажать **F5**.
В верхнем меню появится **📄 CLM**.

> Не появилось → не нажат Ctrl+S на шаге 7, либо код вставлен не полностью.

### 9. Запустить мастер установки

**CLM → 🛠 Установка и проверка → 🚀 Запустить мастер установки**

1. Поле оставить **пустым** → OK
2. Google попросит доступ → **Разрешить**
3. Экран «Google не проверил это приложение»:
   **Дополнительные настройки** → **Перейти к Dereknet CLM (небезопасно)** → **Разрешить**

> Это предупреждение нормальное: приложение написано внутри компании
> и не публиковалось в магазине Google.

Появится список созданного. Мастер сделал:
- 6 папок на Диске (`1. Входящие` … `6. Шаблоны`)
- листы `Журнал`, `Реестр договоров`, `Справочник ошибок`
- автозапуск: проверка входящих каждые 5 минут, сводка на почту в 09:00

### 10. Указать ключ OpenAI

**CLM → 🛠 → 🔑 Указать ключ OpenAI** → вставить ключ `sk-...`

Ключ хранится в настройках скрипта, в таблице не виден.

### 11. Указать email ответственного

**CLM → 🛠 → 📧 Указать email ответственного** → своя рабочая почта.

Сюда приходят уведомления о проблемах и утренняя сводка.

### 12. Положить шаблон и подпись

На Диске появилась папка `Dereknet CLM` → внутри `6. Шаблоны`.

Положить туда:
- **шаблон NDA** — обязательно как **Google Документ**.
  Если файл `.docx` → открыть его → **Файл → Сохранить как Google Документ**
- **PNG с подписью директора**

> Без подписи система работает, но в договоре будет прочерк `_______`.

### 13. Найти шаблон и подпись

**CLM → 🛠 → 🔍 Найти шаблоны и подпись**

Должно написать, что нашло оба файла.

### 14. Проверить систему

**CLM → 🛠 → 🩺 Проверить систему**

Все строки должны быть ✅. Каждый ❌ содержит подсказку, что нажать.

### 15. Собрать пробный договор

**CLM → 🛠 → 🧪 Тест: собрать пробный договор**

Проверяет, что в шаблоне нет мест, которые скрипт не умеет заполнять.
Пробные файлы удаляются автоматически.

Ожидаемо: `✅ Шаблон исправен`

> `❌ ПУСТЫЕ_ПЛЕЙСХОЛДЕРЫ` → в шаблоне есть `{{ТОКЕН}}`, которого система не знает.
> В сообщении будет его имя: убрать из шаблона или добавить поле в `06_Render.gs`.

**На этом система работает.** Можно положить файл в `1. Входящие` и через 5 минут получить договор на почту.

# Почему три файла, а не один

Это устройство Apps Script, не наше решение. Платформа различает три типа файлов
и обращается с ними по-разному:

| Файл | Что это | Почему отдельно |
|---|---|---|
| `Код.gs` | Серверный код | Выполняется на серверах Google |
| `Index.html` | Страница формы | Отдаётся в браузер сотрудника. Код ищет её по имени: `HtmlService.createTemplateFromFile('Index')`. Внутри `.gs` она лежать не может |
| `appsscript.json` | Настройки проекта | Не код вообще. Google читает его сам: какие разрешения запросить, какие службы подключить, как публиковать |

Аналогия: в обычном веб-проекте тоже нельзя слить в один файл бэкенд,
HTML-страницу и `package.json`.

**Одиннадцать модулей** в один `Код.gs` склеить как раз можно — это просто код,
и Apps Script всё равно выполняет все `.gs` в общей области видимости.
Это и делает `npm run build`: собирает `src/*.gs` в `build/Code.gs` в алфавитном
порядке имён (порядок важен — от него зависит, что успеет объявиться раньше).

В репозитории исходником остаётся `src/` — там 11 файлов по 200–380 строк вместо
одного на 3243. Править удобнее, git показывает понятные диффы, тесты гоняются
по модулям. `build/Code.gs` — производная, редактировать её нельзя,
её перезапишет следующая сборка.

# Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Меню 📄 CLM не появилось | Ctrl+S в редакторе, затем F5 в таблице |
| «Drive API не подключён» | `appsscript.json` вставлен не полностью — повторить шаг 6 |
| «У вас нет доступа к файлу» | Мастер запущен не тем аккаунтом — проверить аватарку |
| Форма → «Отказано в доступе» | Развёрнута с доступом «Только я» — переразвернуть по шагу 16 |
| Триггеры не срабатывают | Запустить `processInbox` вручную из редактора и разрешить доступ |
| `ПУСТЫЕ_ПЛЕЙСХОЛДЕРЫ` | В шаблоне лишний `{{ТОКЕН}}`. Система специально не выпускает такой договор |
| В договоре `—` вместо значения | Поле пришло пустым. Так задумано: видно, что пусто, а не потеряно |
| Письма не приходят | Не задан email ответственного (шаг 11) |

Все сообщения об ошибках с расшифровкой — на листе **«Справочник ошибок»** в таблице.
