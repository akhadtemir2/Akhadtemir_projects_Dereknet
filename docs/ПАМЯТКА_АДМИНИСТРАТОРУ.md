# Памятка администратору Google Workspace dereknet.com

Одностраничная инструкция. Весь остальной контекст не нужен.

**Суть просьбы:** система автоматического создания договоров Dereknet сейчас
работает на учебном аккаунте `atemir23@apec.edu.kz` (чужой Workspace). Её переносят
на `info@dereknet.com`. Нужно два действия с вашей стороны.

---

## Действие 1 — подтвердить, что `info@dereknet.com` это пользователь ⏱ 2 минуты

Откройте **admin.google.com → Каталог → Пользователи** и найдите `info@dereknet.com`.

| Что видите | Что делать |
|---|---|
| Есть в списке **Пользователей** | ✅ Ничего не нужно, сообщите «это пользователь» |
| Есть только в **Группах** | Создать пользователя `clm@dereknet.com` (см. ниже) |
| Нет нигде | Создать пользователя `clm@dereknet.com` |

**Почему это важно:** группа Google не может владеть проектом Apps Script и не может
запускать задачи по расписанию. Система на группе просто не заработает.

**Если нужно создать пользователя:**
Каталог → Пользователи → **Добавить пользователя**
- Имя: `Dereknet CLM`
- Email: `clm@dereknet.com`
- Занимает одну лицензию Workspace
- Пароль передайте ответственному за систему

---

## Действие 2 — создать Общий диск ⏱ 10 минут

Можно сделать позже, система заработает и без этого. Но пока Общего диска нет,
файлы принадлежат конкретному аккаунту, а не компании — то есть исходная проблема
решена лишь наполовину.

**Зачем нужен Общий диск:** файлы на нём принадлежат **организации**. Сотрудник
уходит — файлы, договоры и реестр остаются. На обычном «Моём диске» файлы уходят
вместе с человеком.

### Как сделать

1. Войдите в Google Диск под **любым** аккаунтом dereknet.com (не обязательно админским).
2. Слева → **Общие диски** → **Создать общий диск** → название `Dereknet CLM`.
3. Откройте диск → **Управление участниками** → добавьте:

   | Кого | Права | Зачем |
   |---|---|---|
   | `info@dereknet.com` *(или `clm@dereknet.com`)* | **Менеджер** | От него работает система |
   | Бухгалтерия, менеджеры | **Читатель** | Договоры они получают ссылкой из письма, больше не нужно |
   | Юрист | **Автор** | Правит черновики |

4. Сообщите ответственному ID диска — часть ссылки после `/folders/`.

### Если Google не даёт добавить участника

Admin Console → **Приложения → Google Workspace → Диск и Документы →
Настройки общего доступа** → проверьте, что общий доступ внутри организации разрешён.

## Чего делать НЕ нужно

- ❌ Не нужно давать доступ аккаунту `atemir23@apec.edu.kz` — при выбранной схеме
  переноса внешний участник не требуется, файлы копируются аккаунтом Dereknet.
- ❌ Не нужно менять настройки безопасности домена, DNS или SPF.
- ❌ Не нужно ничего покупать: Google Workspace на dereknet.com уже работает
  (проверено по MX-записям 27.08.2026). Единственная возможная трата — одна лицензия,
  если решите завести отдельный `clm@dereknet.com`.

## Что появится в домене после переноса

| Объект | Владелец | Примечание |
|---|---|---|
| Общий диск `Dereknet CLM` | Организация | Папки, шаблоны, готовые договоры |
| Google Таблица «Журнал» | Организация | Журнал обработки + реестр договоров |
| Проект Apps Script | `info@` / `clm@` | Привязан к таблице |
| Веб-приложение | `info@` / `clm@` | Доступ только сотрудникам dereknet.com |

Внешние запросы система делает только к двум адресам:
`api.openai.com` (распознавание документов) и `ba.prg.kz` (проверка контрагентов по БИН).
Данные никуда больше не уходят.
